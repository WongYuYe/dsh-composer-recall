# Product Document

## 1. Product Positioning

`pokemon-claw` 是一个面向 OpenClaw 运行状态的可视化看板。

它的核心价值不是“替代 OpenClaw 本体”，而是把原本偏命令行、偏运维的状态信息，整理成一个适合日常查看、快速判断、轻量处理的控制台。

当前版本更接近：

- 一个单页实时运行看板
- 一个多 Agent 状态总览台
- 一个任务异常处理入口
- 一个介于“运维看板”和“任务观察台”之间的前端产品

## 2. Product Goals

当前产品目标有四个：

1. 让用户在一个页面内看清 OpenClaw 当前是否在线、是否健康、是否有任务、是否有异常。
2. 让用户能快速切换不同 Agent 视角，理解各 Agent 的位置、状态和最近活动。
3. 让用户在任务阻塞或异常时，直接在页面内执行最小处理动作。
4. 让产品既能连接本地 OpenClaw，也能连接远程已部署的服务。

## 3. Target Users

当前版本主要服务三类用户：

- OpenClaw 的实际使用者：希望知道“现在谁在跑、跑到哪了、有没有卡住”。
- 轻量运维/开发者：希望快速判断服务是否在线、任务是否堆积、Agent 是否异常。
- 演示与观察场景的使用者：希望用可视化地图和状态面板展示多 Agent 运行状态。

## 4. Core Concepts

### 4.1 Agent

Agent 是产品的第一核心对象。当前产品默认围绕四个 Agent 展示：

- `main`
- `research`
- `executor`
- `ops`

每个 Agent 至少包含这些信息：

- `id`
- `name`
- `enabled`
- `zone`
- `status`
- `session`
- `position / mapPosition`

### 4.2 Task

Task 是产品的第二核心对象。当前界面聚焦的是“当前任务”和“可操作任务”，而不是完整项目管理。

当前任务能力包括：

- 读取 task stats
- 读取 task runtime
- 显示当前任务标题、状态、进度、失败信息
- 在满足条件时触发 `retry`
- 在满足条件时触发 `resolve`

### 4.3 Zone

Zone 是地图和状态判断的桥梁。当前产品固定围绕三个业务区：

- `rest`
- `work`
- `alarm`

它们同时影响：

- 地图渲染主题
- 右侧状态文案
- 告警感知
- Agent 的默认聚集区域

### 4.4 Runtime

Runtime 表示系统当前是否在跑任务、是否排队、是否失败。

当前产品关心的 runtime 信息包括：

- `queued`
- `running`
- `failed`
- `currentTask`
- `nextTask`

### 4.5 Timeline

Timeline 是面向“最近发生了什么”的轻量事件流，不是完整审计日志。

它主要服务于：

- 当前状态解释
- 最近任务变化摘要
- 最近异常提示

## 5. Main Use Cases

### 5.1 打开看板，快速判断系统状态

用户打开页面后，希望在 5 秒内回答这些问题：

- OpenClaw 在线吗
- 当前在哪个区域
- 当前是否有任务在跑
- 当前是否有告警
- 当前关注的 Agent 是谁

### 5.2 切换 Agent，观察多 Agent 状态

用户可以从 `main` 切换到其他 Agent。

切换后应发生：

- 右侧主视图切换到该 Agent
- 地图聚焦切换到该 Agent
- 其他未选中的 Agent 仍继续显示和移动
- 未选中的 Agent 透明度更低，弱化视觉权重

### 5.3 看到异常后做最小处理

当任务阻塞或失败时，用户可以在页面执行：

- `retry`
- `resolve`

这类动作当前定位为“最小操作入口”，而不是完整任务编排系统。

### 5.4 在本地模式和远程模式之间切换

产品支持两种运行模式：

- 远程模式：前端跑在本地或服务器，数据来自远程已部署服务
- 本地模式：前端连接本地后端，再由后端调用本地 `openclaw`

## 6. Information Architecture

当前页面由两大块组成。

### 6.1 主区域：地图视图

主区域由 Phaser 地图承载，负责：

- 展示当前聚焦 Agent
- 展示其他 Agent 的位置
- 用区域主题表达 `rest / work / alarm`
- 用动画表达 Agent 正在活动

### 6.2 侧边栏：状态与操作面板

侧边栏当前包含三张卡片：

1. 任务总览
2. Agent 总览
3. 最近变化

它们分别回答：

- 当前任务是什么、是否异常、能否处理
- 四个 Agent 现在各自在哪、状态如何
- 最近发生了什么

## 8. Current State Logic

当前产品的状态不是完全依赖某一个字段，而是由多个来源综合推导。

### 8.1 Zone 判定

当前 zone 主要由任务运行情况推导：

- 有失败任务时优先进入 `alarm`
- 有运行中任务时进入 `work`
- 否则进入 `rest`

### 8.2 Mode 判定

当前 mode 主要按以下优先级收敛：

- 失败优先进入异常状态
- 有运行任务时进入运行态
- 无任务时进入待命/休息态

### 8.3 Focused Agent 判定

当前聚焦 Agent 的规则是：

- 默认 `main`
- 如果用户主动切换，则使用用户选择
- 如果用户选择的 Agent 不存在，则回退到可用 Agent

### 8.4 地图渲染逻辑

地图的视觉规则是：

- 选中 Agent 作为主角色
- 非选中 Agent 以弱化 Marker 或弱化角色展示
- 室内视图和城镇视图共存
- 不同 Agent 拥有不同巡游节奏和路径

## 9. Runtime Modes

### 9.1 Remote Mode

远程模式是当前产品默认模式。

特点：

- 页面由本地或服务器前端提供
- 数据来自远程 `/api` 与 `/ws`
- 不依赖当前机器安装 `openclaw`

适用场景：

- 线上看板
- 轻量演示
- 多人共用一个部署实例

### 9.2 Local Mode

本地模式适合开发、调试、单机运行。

特点：

- 本地后端直接调用本地 `openclaw`
- 前端通过本地聚合层读取状态

适用场景：

- 调试 OpenClaw CLI
- 验证本地 profile
- 单机实验

## 10. Current Boundaries

当前版本仍有明确边界。

### 10.1 它不是完整任务系统

当前任务能力偏“观测 + 最小操作”，不是完整的任务管理平台。

暂时没有：

- 完整任务列表页
- 任务过滤和检索
- 任务详情页
- 任务历史追踪
- 项目级视图

### 10.2 它不是完整运维平台

当前产品会显示在线状态和部分诊断，但没有完整可观测性能力。

暂时没有：

- CPU / 内存 / 延迟图表
- 服务进程管理面板
- 异常告警订阅
- 变更审计

### 10.3 它不是完整多租户控制台

当前主要围绕一个 OpenClaw 运行实例展开。

暂时没有：

- 多 workspace 切换
- 多环境切换
- 多租户权限模型

## 11. Current Product Problems

结合当前代码与本次线上运行问题，现阶段主要问题有六类。

### 11.1 状态同步链路仍偏重

虽然已经收敛了一轮，但底层对 `openclaw status / health / cron` 的依赖仍然较重。

### 11.2 OpenClaw 运行层和可视化层耦合偏深

当前页面体验、状态接口、任务接口，都很依赖 OpenClaw 的实时可用性。

### 11.3 前端信息密度还不够分层

现在首页把“主任务、Agent、事件流、地图”都放在同一个看板上，适合观察，但不适合深度排查。

### 11.4 任务动作语义偏窄

当前只有 `retry / resolve`，无法覆盖更完整的人工干预流程。

### 11.5 运行诊断能力不足

出了问题时，页面能告诉你“失败了”，但还不能充分回答“为什么失败、卡在哪、该先看哪”。

### 11.6 文档和产品语言还不够统一

当前 README、运行说明、界面文案和产品视角之间仍然有提升空间。

## 12. Feature Improvement Directions

下面是建议的产品演进方向，按价值和优先级排序。

### 12.1 P0：稳定性与可观测性

这是当前最优先方向。

建议补齐：

- 状态缓存分层
- stale-while-refresh 常态化
- 更清晰的错误分级
- OpenClaw 依赖超时保护
- 页面内诊断信息卡
- 服务负载、采样频率、最近错误的只读展示

目标是把产品从“能看”提升到“出了问题也能看懂”。

### 12.2 P1：任务中心

把当前“任务摘要 + 两个按钮”扩展成真正的任务面板。

建议补齐：

- 当前任务卡增强
- 最近任务列表
- 阻塞任务列表
- 每个任务的失败原因、最近更新时间、所属 Agent
- 操作后的结果反馈和回执

目标是把产品从“运行看板”扩展到“轻量任务控制台”。

### 12.3 P1：Agent 视角深化

把多 Agent 从“可切换”提升到“可比较、可理解”。

建议补齐：

- Agent 最近活动历史
- Agent 心跳状态
- Agent 当前会话资源占用
- Agent 角色标签与职责说明
- Agent 对比视图

目标是让用户不仅知道“有四个 Agent”，还知道“这四个 Agent 分别在干什么”。

### 12.4 P1：异常处理闭环

让异常不只停留在展示层。

建议补齐：

- 失败原因分类
- 标准处理建议
- 一键重试前的确认
- 处理结果状态回传
- 异常恢复后的时间线记录

目标是让页面具备基础“运维闭环”。

### 12.5 P2：历史与回放

当前时间线只适合看最近变化，不适合做复盘。

建议补齐：

- 状态快照历史
- 任务状态变化历史
- Agent 位置回放
- 告警出现与恢复时间线

目标是把产品从“实时看板”扩展成“可复盘的运行台”。

### 12.6 P2：多环境与权限

当产品走向长期使用时，这部分会越来越重要。

建议补齐：

- 环境切换
- 多实例接入
- API key / token 管理
- 只读模式与操作模式分离
- 操作审计

## 13. Suggested Product Roadmap

### Phase 1

- 先把状态同步成本压下来
- 增加诊断信息
- 稳定线上运行

### Phase 2

- 做任务中心
- 做 Agent 深化
- 做异常处理闭环

### Phase 3

- 做历史回放
- 做多环境
- 做权限与审计

## 14. Product Summary

`pokemon-claw` 当前最适合被定义为：

一个面向 OpenClaw 的多 Agent 可视化运行看板。

它当前已经具备：

- 运行态展示
- 多 Agent 切换
- 任务摘要
- 基础异常处理
- 本地 / 远程双模式

它下一阶段最值得做的，不是继续堆页面元素，而是沿着这条路线推进：

- 先把运行稳定性和诊断能力做扎实
- 再把任务和 Agent 两条产品线补完整
- 最后再进入历史、权限、多实例这些更长期的能力建设
