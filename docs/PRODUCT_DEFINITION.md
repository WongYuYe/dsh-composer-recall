# open-pokemon-claw 产品定义

## 1. 产品一句话

`open-pokemon-claw` 是一个面向 OpenClaw 的可视化运行舱。它通过空间化、游戏化的界面，把 AI 运行状态、任务流转和异常信号转化为一眼可读的持续观察体验，并提供最小控制闭环。

## 2. 产品定位

它不是 OpenClaw 本体，也不是官方控制台的替代品。

它的定位是：

- 一个更适合长期挂着观察的运行看板
- 一个更直观表达 OpenClaw 当前状态的空间化界面
- 一个只承载少量高频动作的轻控制面板

## 3. 目标用户

### 核心用户
- 长期运行 OpenClaw 的个人开发者 / 运维型用户
- 希望快速知道 AI 当前状态的人
- 偏好“扫一眼就知道大概情况”的用户

### 次级用户
- 需要演示 OpenClaw 状态的人
- 希望把系统运行过程人格化、场景化呈现的人
- 想把页面长期挂在第二屏 / 浏览器标签页 / 大屏的人

## 4. 核心价值

### 4.1 状态具象化
将抽象系统状态映射为具体空间与氛围：
- work
- rest + room
- rest + outdoor
- alarm

### 4.2 降低查看成本
用户无需先理解 session、cron、health、runtime 等抽象数据，就能快速判断：
- 系统是否在线
- 当前在做什么
- 是否异常
- 是否需要介入

### 4.3 最小控制闭环
支持少量高频控制动作：
- retry
- resolve
- agent turn

### 4.4 低打扰运行
展示层不应反向影响 OpenClaw 主体，因此产品运行必须满足：
- 独立进程
- 非 dev/watch
- 缓存优先
- 无客户端不轮询
- 按需刷新

## 5. 产品边界

## 做什么
- 状态看板
- 任务可视化
- 异常感知
- 最小动作闭环
- 长期常驻观察

## 不做什么
- 不替代官方 OpenClaw Control UI
- 不承担复杂配置管理
- 不变成全功能调度后台
- 不成为重表单、重运维型后台系统

## 6. 主要使用场景

### 场景 A：挂屏观察
用户打开页面长期挂着，用最低认知成本持续判断系统状态。

### 场景 B：异常介入
页面从正常态切到报警态后，用户立刻知道：
- 为什么报警
- 当前任务是什么
- 是否阻塞
- 可以点什么恢复

### 场景 C：对外演示
用于展示一个“活着的”OpenClaw 系统，而不是静态日志页面。

## 7. 核心功能结构

### 7.1 地图层
职责：表达当前状态空间

输入：
- zone
- scene
- alertLevel
- position
- idleActivity

输出：
- 场景切换
- 氛围变化
- 角色位置 / 活动感

### 7.2 状态层
职责：表达当前发生了什么

包括：
- 当前任务
- 模式
- 报警等级
- 最近更新时间
- 队列摘要
- 连接状态

### 7.3 时间线层
职责：表达最近发生了什么

包括：
- 状态事件
- 任务事件
- 异常事件
- 用户动作结果

### 7.4 动作层
职责：完成最小控制闭环

包括：
- retry
- resolve
- agent turn

### 7.5 聚合服务层
职责：对 OpenClaw 做低打扰聚合

原则：
- 独立进程运行
- start 模式
- 低频轮询
- 无客户端不轮询
- 子路径兼容
- 对 CLI 输出噪音具备容错能力

## 8. 关键产品原则

### 原则 1：一眼可读
页面必须优先回答：
- 现在在哪个状态
- 在做什么
- 有没有问题

### 原则 2：异常优先
出现问题时，优先呈现：
- 异常等级
- 原因摘要
- 是否阻塞
- 下一步动作

### 原则 3：轻控制，不重管理
它更像运行舱，不像后台配置中心。

### 原则 4：持续陪伴
默认使用方式是“挂着看”，不是频繁点进去操作。

### 原则 5：展示从属于主体
任何展示逻辑都不应该压垮 OpenClaw。

## 9. 当前已具备能力
- 独立前端聚合服务
- 子路径部署兼容
- WebSocket 状态流
- 状态接口
- diagnostics
- 任务统计 / 运行态聚合
- 最小任务动作
- 低打扰轮询优化
- 生产启动脚本
- CLI JSON 污染容错解析

## 10. 当前阶段目标

从“可运行的像素 Demo”，推进到“可长期挂着使用的 OpenClaw 运行舱”。

当前最重要的四个方向：
1. 稳定
2. 低打扰
3. 一眼可读
4. 最小闭环控制
