# open-pokemon-claw · 4 周产品路线图

## 总目标

4 周后把项目推进到以下状态：

- 连上真实 OpenClaw runtime
- 可以查看多 agent 状态
- 可以执行最小控制动作
- 可以查看任务与工具调用轨迹
- 有一批真实用户连续使用并反馈
- 能证明这是控制台，不只是像素皮肤

---

## Week 1：接通真实 runtime，完成去 mock

### 目标
把项目从“概念演示”推进到“真连 OpenClaw”。

### 本周必须完成
1. 梳理前后端已有 mock 数据入口与真实数据入口
2. 定义统一状态模型：`agent / task / event / alert`
3. 前端默认走真实后端，不再依赖 mock JSON
4. 地图层完成真实状态映射：
   - idle
   - running
   - waiting
   - blocked
   - failed
5. 明确 `main / research / executor / ops` 的地图落点与视觉语义

### 本周验收标准
- 可以演示一个真实连着 OpenClaw 的地图页
- 不依赖假数据也能展示 agent 状态变化
- 能说明每个状态在 UI 上如何表达

---

## Week 2：补最小控制闭环

### 目标
从“能看”变成“能管”。

### 本周必须完成
1. 右侧详情面板
2. 最小控制动作：
   - 查看 agent 当前任务
   - 派发新任务
   - 停止任务
   - 重试任务
3. 展示 `main -> subagent` 任务流转关系
4. 建立任务详情卡片：
   - title
   - status
   - ownerAgent
   - startedAt
   - updatedAt
   - latestEvent

### 本周验收标准
- 可以从地图点击进入 agent 详情
- 可以发起一次真实任务或对运行中任务执行控制动作
- 可以看懂任务归属和当前执行方

---

## Week 3：补时间线与异常处理

### 目标
让产品具备真实使用价值，而不只是好看。

### 本周必须完成
1. 任务/agent 时间线视图
2. 错误和阻塞状态高亮：
   - failed
   - blocked
   - waiting_user
   - timeout
   - tool_error
3. 信息增强模式：地图模式 / 调试模式切换
4. 最近 tool call / event 摘要展示

### 本周验收标准
- 用户能回答“它刚刚做了什么、为什么卡住、我该不该接管”
- 错误状态在 3 秒内可被发现
- 地图不再只是装饰，而是诊断入口

---

## Week 4：真实用户验证与方向判断

### 目标
验证项目是“爆款 demo”还是“可持续产品”。

### 本周必须完成
1. 邀请 5~10 个真实 OpenClaw 用户试用
2. 设计固定验证任务：
   - 看谁在忙
   - 找失败任务
   - 发任务
   - 停任务
   - 找最近一次 tool call
3. 收集三类反馈：
   - 喜欢但不用
   - 真有帮助
   - 哪里卡手
4. 输出一份产品判断报告

### 本周验收标准
- 至少有一部分用户愿意把它作为日常控制台的一部分
- 得到清晰结论：继续产品化 / 继续 showcase / 重新聚焦场景

---

## 优先级

### P0
- 真数据
- 真控制
- 真诊断
- 真用户反馈

### P1
- 多 agent 语义系统
- 任务关系链可视化
- 可复用的状态组件

### P2
- 更多皮肤
- 更复杂地图动画
- 世界观扩展
- 多 runtime 通用化

---

## 关键原则

1. 先证明是控制台，再追求更炫
2. 地图负责感知，面板负责操作，时间线负责诊断
3. 风格不是护城河，交互范式才是
4. 点赞不算验证，连续使用才算
