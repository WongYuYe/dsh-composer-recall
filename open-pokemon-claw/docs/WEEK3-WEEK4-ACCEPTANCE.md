# Week 3 / Week 4 验收补充

## Week 3 已落地能力

- 时间线视图：右侧新增“最近事件 / Tool Call”列表
- 异常高亮：对 failed / blocked / timeout / waiting_user / tool_error / 离线断流文案做红色高亮
- 模式切换：支持“地图模式 / 调试模式”切换
- 最近摘要：把当前任务、队列、阻塞判断、最近事件收敛成一句诊断摘要
- WebSocket 可观测性：后端新增 hello / snapshot / patch 流和 `/api/openclaw/diagnostics`

## Week 4 固定验收任务入口

应用内固定入口：

1. 看谁在忙
2. 找失败任务
3. 发任务
4. 停任务
5. 找最近一次 tool call

## 应用内验证清单

按钮：`运行应用内验证`

当前会自动检查：

- 状态接口可用
- 任务运行态接口可用
- WebSocket/诊断接口可用（非 mock/demo）

## 用户试用清单

建议让试用者按以下顺序完成：

1. 进入地图模式，判断当前谁在忙
2. 切到调试模式，判断是否存在失败/阻塞
3. 给某个 agent 发一条任务
4. 对失败/阻塞任务做重试或处理完成
5. 从时间线里说出最近一次 tool call / 事件摘要
6. 运行应用内验证，并填写产品判断报告模板

## 产品判断报告模板

- 当前模式：map/debug
- 运行环境：runtime/demo/mock
- 验证结论：通过 / 未通过
- 关键观察：状态链路、任务链路、异常发现速度、是否能定位最近事件
- 用户反馈归类：喜欢但不用 / 真有帮助 / 哪里卡手
- 决策建议：继续产品化 / 继续 showcase / 重新聚焦场景
